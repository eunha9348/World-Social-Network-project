# VMAX 관리자 전용 운영 보고서

작성·요금 확인: 2026-09-15 · 통화: USD · 세금/환전 수수료 별도

이 문서는 운영자에게 별도로 전달하는 문서다. 공개 사이트의 메뉴, 마이페이지, 사용자 리서치 보고서에 포함하지 않는다. 실제 비밀키는 문서에도 적지 않는다. API·DB 구성과 발급 안내만 담는다.

## 1. 지금 준비할 항목

| 설정 | 어디서 얻는가 | 필요 기능 |
|---|---|---|
| OPENAI_API_KEY | OpenAI 프로젝트 API Keys | 재순위화·번역·AI 토론·검사·임베딩 |
| QDRANT_URL | Qdrant cluster 상세 | 의미 검색 저장소 주소 |
| QDRANT_API_KEY | Qdrant cluster 생성/API Keys | 벡터 읽기·쓰기 |
| INGEST_TOKEN | 운영자가 무작위 생성 | 우리 서비스 데이터 반입 인증 |
| ADMIN_EMAILS | 본인 로그인 이메일 | 관리자 작업 권한 |
| LLM_MODEL | 기본 gpt-4.1-mini | 분석 모델 선택 |
| EMBEDDING_MODEL | 기본 text-embedding-3-small | 1,536차원 검색 임베딩 |
| QDRANT_COLLECTION | 기본 polylogue 유지 | 기존 검색 인덱스 이름 |
| SITE_URL | 실제 배포 주소 | Python 수집기의 반입 목적지 |

사이트 표시 이름은 VMAX다. 기존 배포 주소와 내부 collection 기본 이름을 유지해 저장된 데이터 연결을 끊지 않았다. 모델명과 주소는 키가 아니다. 동일 OpenAI 키로 여러 모델을 호출하므로 모델마다 별도 키를 발급할 필요는 없다.

현재 버전에는 실제 corpus가 없다. API 연결만으로 전 세계 데이터가 자동 확보되지는 않는다. HN 공식 수집기와 승인된 JSONL 반입 경로가 포함되어 있다. 언어별 고정 수량은 요구하지 않으며, 승인된 출처의 원문을 실제 검색 실패 사례와 분포에 따라 확대하고 주요 언어·주제별 검색 평가를 별도로 수행한다.

## 2. OpenAI 키 발급 방법

1. [OpenAI Platform](https://platform.openai.com/)에 본인 계정으로 로그인한다. 조직/프로젝트를 확인하고 VMAX 전용 프로젝트를 만든다.
2. Billing에서 결제 수단 또는 크레딧 상태를 확인한다. ChatGPT 사용과 API 운영은 서로 다른 사용 경로이므로 API 계정의 결제 상태를 확인해야 한다.
3. 프로젝트 설정 → API Keys → Create new secret key. 이름은 vmax-server처럼 구분한다. 운영용은 프로젝트 Members → Service account에서 별도 서비스 계정을 만드는 방식도 가능하다.
4. 생성 직후 표시되는 키를 비밀 관리 도구에 저장한다. 다시 표시되지 않는 키를 잃어버리면 새 키를 발급한다.
5. Restricted 권한을 사용할 경우 Chat Completions, Embeddings, Moderations 호출이 가능해야 한다. 읽기 전용 키만으로 이 앱의 POST 호출을 수행할 수는 없다.
6. 배포 설정에서 OPENAI_API_KEY를 Secret으로 등록한다. 코드와 브라우저에는 넣지 않는다.
7. gpt-4.1-mini와 text-embedding-3-small 접근 가능 여부를 확인한다. 모델 변경 시 번역·인용·JSON 응답 검증을 다시 수행한다.

공식 안내: [API 키 찾기](https://help.openai.com/en/articles/4936850-where-do-i-find-my-openai-api-key), [프로젝트·서비스 계정·권한](https://help.openai.com/en/articles/9186755-managing-your-work-in-the-api-platform-with-projects).

### 지출 제한

프로젝트 Settings → Limits → Spend → Edit spend limit에서 월 한도를 설정하고, 실제 요청 차단이 필요하면 Enforce a hard limit을 켠다. 알림만 설정하면 호출이 계속된다. 한도 집계가 즉시 반영되지 않아 소액 초과가 생길 수 있다. 첫 소량 검증은 예를 들어 $10 한도부터 시작하고, 실제 검색·번역 사용량을 확인한 뒤 조정한다. 이는 제안값이며 자동 설정하지 않았다. [공식 spend limit 안내](https://developers.openai.com/api/docs/guides/spend-limits).

## 3. Qdrant와 D1 준비

[Qdrant Cloud](https://cloud.qdrant.io/) 로그인 → Create a Free Cluster → 이름·지역·클라우드 선택 → 생성한다. 생성 시 표시되는 cluster API key를 저장하고 cluster HTTPS URL을 복사한다. 각각 QDRANT_API_KEY와 QDRANT_URL에 넣는다. 이 앱은 문서 1개당 평균 임베딩 1개를 저장하며, 인덱스 dimension은 1536, distance는 Cosine이다. language/source 키워드와 publishedAt datetime 인덱스는 수집기가 생성한다. [공식 시작 안내](https://qdrant.tech/documentation/cloud-quickstart/).

가능하면 운영 서버에는 조회 권한, 수집기에는 쓰기 권한을 따로 발급한다. 현재 환경변수명은 둘 다 QDRANT_API_KEY지만 실행 환경별 값은 다르게 설정할 수 있다. 권한을 분리할 수 없는 요금제/설정에서는 최소 범위를 선택하고 회전 계획을 둔다.

**Cloudflare D1은 별도의 앱용 API 키를 발급하지 않는다.** 현재 Sites가 DB 바인딩과 배포 migration을 연결한다. VMAX는 posts, reports, rooms, messages, profiles, bans, audit, limits 테이블을 사용한다. 개인 프로필은 본인의 인증된 ID로만 읽기/수정하고 마이페이지 응답은 private/no-store로 처리한다.

기존 migration 0000은 보존했고 0001은 profiles 테이블, 0002는 작성자·출처 근거 필드를 추가한다. 별도 Cloudflare 계정에 직접 이전한다면 Workers/D1 생성, 바인딩, migration, 인증 구성을 다시 해야 한다. 이번 코드를 그대로 GitHub Pages에 올려서는 서버 기능이 작동하지 않는다.

## 5. 사용량 기반 구축·번역 비용 예시

계산식: (입력 토큰 × $0.40 + 출력 토큰 × $1.60) / 1,000,000. 임베딩은 입력 토큰 × $0.02 / 1,000,000. 캐시 할인·Batch 할인은 적용하지 않았다. 특정 총 문서 수를 출시 조건으로 두지 않는다.

가정: 원문 1,000건, 반입 시 언어·감성·주장 판별 입력 1,000토큰/건과 출력 80토큰/건, 임베딩 입력 1,125토큰/건. 전체 번역은 반입 시 생성하지 않는다.

| 항목 | 1,000건 기준 | 금액 |
|---|---|---:|
| 언어·감성·주장 판별 입력 | 1M × $0.40 | $0.40 |
| 판별 출력 | 0.08M × $1.60 | $0.128 |
| 임베딩 | 1.125M × $0.02 | $0.0225 |
| 원문 1,000건 반입 합계 | 모델 처리만 | **약 $0.55** |
| 요청 시 번역 1,000건 | 입력 1,000 + 출력 800토큰/건 가정 | **약 $1.68** |

따라서 상용화 전에는 원문 100건을 반입하고 실제로 필요한 상위 결과만 번역하면 모델 비용은 위 가정에서 약 $0.22 수준이다. 동일 원문·목표 언어의 번역은 D1 캐시를 재사용하므로 반복 조회마다 번역 비용이 발생하지 않는다. 원문 길이, 출력 길이, 재시도, 사용자 선택량에 따라 실제 금액은 달라진다.

게시글 구매·수집 계약, 인력 검수, 수집 서버, Qdrant, 호스팅, 세금은 포함하지 않았다. 벡터 저장량도 실제 반입 문서 수에 비례하므로 무료 노드의 메모리와 지연시간을 실측해 확장한다.

## 6. 월 운영 비용 예시

아래 토큰은 **한 사용자 작업에서 발생하는 모든 LLM 호출을 합산한 가정**이다. 실제 사용량 로그를 측정하기 전의 예산 시나리오다.

| 작업 | 월 횟수 | 작업당 입력/출력 토큰 | 월 모델 비용 |
|---|---:|---|---:|
| 검색 재순위화 | 10,000 | 5,000 / 200 | $23.20 |
| 검색 임베딩 | 10,000 | 입력 40 | $0.008 |
| 요청 시 번역 | 2,000개 원문 | 800 / 650 | $2.72 |
| 원문 보고서·선택 비교 | 1,000 | LLM 미사용 | $0 |
| AI 2역할 토론 1라운드·검사 | 2,000 | 9,000 / 1,200 | $11.04 |
| 사용자 발언 문맥 검사 | 10,000 | 500 / 80 | $3.28 |
| 회의 전체 요약·검사 | 200 | 22,000 / 3,000 | $2.72 |
| 합계 | 위 가정 | 추가 반입 제외 | **약 $42.97/월** |

10배 호출량에서는 캐시 적중률과 작업별 토큰을 별도로 적용해야 하므로 단순 사용자 수만으로 비용을 추정하지 않는다. 신규 원문은 번역 없이 판별·색인하고, 번역은 사용자가 실제로 연 결과에만 발생한다. 기본 보고서는 원문 발췌 방식이므로 모델 비용이 없다. 긴 대화 이력과 실패 후 재시도는 추가 비용이 발생한다.

대규모 토론에서는 4초마다 조회하므로 활성 접속자 100명이 하루 1시간씩 사용하면 약 90,000회의 조회/일이다. 각 조회가 읽는 메시지 행 수에 따라 DB 비용이 늘어난다. 이는 현재 구현에서 계산한 예시이며 실측이 아니다.

## 7. 설정·검증 순서

1. 위 두 외부 서비스의 키와 주소를 확보한다. 새 키를 이 보고서에 적지 않는다.
2. Python에서 `secrets.token_urlsafe(32)`로 INGEST_TOKEN을 생성한다. 이는 외부 발급 상품이 아니며 발급 비용이 없다.
3. 배포 관리자 환경변수 화면에 값을 입력한다. OPENAI_API_KEY, QDRANT_API_KEY, INGEST_TOKEN은 Secret으로 설정한다. SITE_URL은 수집기 실행 환경에만 있어도 된다.
4. LLM_MODEL=gpt-4.1-mini, EMBEDDING_MODEL=text-embedding-3-small, QDRANT_COLLECTION=polylogue로 시작한다. 기존 collection 이름 변경 시 데이터 이동 또는 재색인이 필요하다.
5. 환경변수 변경을 적용하여 재배포한다. 사용자 사이트에는 연결 정보가 나타나지 않는다.
6. 승인된 실제 JSONL 20~100건을 반입하고 검색·인용·번역을 검토한다. 이후 언어별 수집량을 늘린다.
7. 두 로그인 계정으로 서로의 개인 보고서·프로필이 보이지 않는지, 공개 토론을 만든 보고서만 공유되는지 확인한다.
8. 사용자 발언·AI 발언의 검사 실패 시 저장이 차단되는지 확인한다. 모든 검사가 완벽하다고 가정하지 않는다.
9. 마이페이지의 저장·새로고침·본인 보고서와 참여 토론 복원을 검증한다.

실제 API 키를 연결하지 않은 상태에서는 코드·타입·배포 빌드를 검증할 수 있지만 유료 API 동작과 모델 품질을 검증했다고 말할 수 없다. 실제 corpus 및 정확도 검증은 계속 미완료다.

## 8. DB 운영과 문제 해결

D1은 원문과 사용자 데이터를 보관하고 Qdrant는 벡터와 검색 필터를 보관한다. 일일 D1 백업과 Qdrant snapshot 정책을 정한다. 원문 삭제 시 D1에서 노출을 막고 같은 ID의 Qdrant point도 삭제한다. 기존 보고서의 원문 스냅샷과 파생 토론은 별도 처리해야 한다. 자동 전파 삭제는 아직 구현하지 않았다.

관리자 작업은 `/api/admin`에서 권한 검사 후 실행한다. 공개 사이트의 운영 패널은 제거했다. 정지 해제는 action=unban과 user ID, 원문 삭제는 action=deletePost와 post ID를 전달하는 관리자 요청이다. 관리자 토큰은 브라우저 코드나 공유 URL에 넣지 않는다. 문서의 cURL 예시 대신 운영자 전용 API 클라이언트에서 비밀값을 보관해 사용한다.

| 증상 | 관리자 확인 사항 |
|---|---|
| 분석 기능 준비 중 | OPENAI_API_KEY, 배포 환경 반영 |
| 요청 실패/502 | 모델 접근, 결제·한도, 제공자 상태 |
| 429 | 사용자 한도 또는 제공자 spend/rate limit |
| 검색 품질 저하 | 벡터 모델·1536차원·collection·언어/날짜 필터 |
| 프로필 저장 실패 | 로그인, 0001 migration 적용, 입력 길이 |
| 요약 중 멈춤 | rooms.closed=2 잠금 상태 및 실패 로그 확인 |
| 로그인/접근 문제 | Sites 공개 접근과 개인 데이터 소유자 검사 |

API 키 유출 시 제공자에서 즉시 폐기하고 새 키를 등록·재배포한다. 저장소 기록 삭제만으로 키가 안전해지는 것은 아니다. 문서를 공개 사이트에 업로드하지 않는다. 원문/API 문서의 요금과 발급 화면은 변경될 수 있으므로 실제 결제 전 위 공식 링크를 다시 확인한다.

## 9. 출처·작성자와 허위 정보 방지

전 세계 커뮤니티 후보 목록은 COMMUNITY_CATALOG.md와 사이트 커뮤니티 지도에 제공한다. 목록은 연동 완료나 세계 인기 순위를 뜻하지 않는다. 실제 저장된 출처별 건수가 있는 경우에만 검색으로 연결한다. 현재 실제 원문은 0건이다. Reddit·Instagram·Facebook·LinkedIn·링커리어·리멤버의 범용 수집 커넥터와 수집 권한은 확보하지 않았다. 각 운영자의 공식 개발자 정책·계약·접근 범위를 먼저 확인해야 한다. 공개 홈페이지가 있다고 해서 게시글을 자유롭게 대량 재배포할 권리가 생기는 것은 아니다.

검색은 기본 상위 10개를 보여주며 5/10/20/30개로 선택할 수 있다. 원문, 작성자 프로필, 관찰 시각, 팔로워 수·직업의 근거 URL을 함께 반입한다. 확인하지 못한 작성자는 '확인되지 않음'으로 표시한다. 팔로워·직업은 없는 값을 추측하지 않는다. 출처 정보 충실도 점수는 본문·링크 30점, 작성자·프로필 25점, 메타데이터 근거·시각 25점, 직업 근거 20점이다. 근거가 있는 팔로워 수만 최대 5점의 보조 신호로 사용하고 동일 출처 작성자는 최대 2건이다. 이 점수는 진실성·전문성 인증이 아니다. 프로필의 자기소개와 실제 자격 검증은 다르다. 운영자 반입 메타데이터를 신뢰하는 구조이므로 출처 기록의 무결성을 별도 검수해야 한다.

연구 보고서와 의견 비교는 새로운 사실을 생성하지 않고 저장된 원문을 직접 발췌한다. AI 토론에는 실제 게시글 ID와 원문에 정확히 존재하는 인용을 요구하고 불일치하면 응답을 보류한다. AI의 질문은 가설·검토로 표시한다. 종료 보고서는 전체 대화를 구간별로 살펴 정확히 일치하는 발언을 발췌하며 전체 기록을 함께 제공한다. 합의를 자동으로 단정하지 않는다.

할루시네이션 0%는 보장할 수 없다. 원문 자체가 허위일 수 있고 번역·감성·주장 라벨·AI 질문도 오류가 있을 수 있다. 인용 일치 검사는 문맥의 정확성이나 주장의 진실성을 증명하지 않는다. 보고서는 검색 표본의 반응이며 전체 인구의 여론조사가 아니다. 출시 전에 언어별 사람이 판정한 평가셋과 오탐·누락 검토가 필요하다.

## 10. 배포·운영자 인수 순서

소스 ZIP을 풀고 비공개 GitHub 저장소에 업로드한다. 실제 키·원문 corpus·개인정보를 커밋하지 않는다. 현재 배포는 Sites 인증 및 Workers/D1을 사용한다. GitHub에 업로드하는 것만으로 호스팅이 바뀌지 않는다. 코드 수정 후 타입 검사와 빌드, migration 확인, 동일 사이트로 재배포한다. 다른 호스팅으로 이전할 때는 인증·DB 바인딩부터 변경해야 한다.

관리자 사용 절차: 로그인 → 마이페이지에 본인 프로필 저장 → 승인된 원문 반입 → 실제 검색 모드 → 결과 선택 및 비교 → 1–5페이지 보고서 생성 → 공유 안내 확인 후 토론 개설 → 사용자 또는 AI 역할과 토론 → 음성 초안 확인 후 전송 → 종료 및 요약 보고서 확인. API/DB 설정은 공개 사용자 메뉴에 표시하지 않는다.

구현 범위: 24개 주요 언어 필터, BCP-47 원문 반입, 원문 1회 저장, 공통 다국어 임베딩, 현재 표시 결과의 요청 시 LLM 번역과 D1 캐시. 언어별 별도 RAG 모델이나 고정 수량 목표는 사용하지 않는다. 현재 실제 corpus와 품질 평가는 미완료다. 동시 오디오 회의는 미구현이며 현재는 음성 입력을 텍스트로 바꾸는 턴 방식 토론이다. 대화 토큰이 초기화될 때 자동으로 이 작업을 재개하는 기능은 없다. STATUS.md와 수집 checkpoint로 이어갈 수 있다.
