# VMAX — 설계 및 구현 명세

## 제품의 핵심

금융·브랜드·마케팅 주제에 대한 커뮤니티 원문을 다국어로 찾고, 근거를 비교하고, 보고서를 중심으로 사람이 AI와 함께 토론한다. 검색 결과는 전체 세계 여론이 아니라 수집된 출처에서 검색된 표본이다.

## 범용 다국어 검색·번역 설계

VMAX는 언어별로 RAG 모델이나 번역 corpus를 따로 만들지 않는다. 모든 원문을 원래 언어로 한 번만 보존하고 공통 다국어 임베딩 공간에 색인한다. 사용자가 번역을 요청한 화면의 상위 결과만 LLM으로 번역하고, 동일 원문·목표 언어의 결과는 D1에 캐시한다. 특정 언어의 고정 수량을 채우는 것보다 실제 출처·주제·기간의 다양성과 평가 품질을 우선한다.

1. 커넥터가 원문·출처 URL·게시 시각·수집 시각을 반입한다.
2. NFKC 정규화, URL 기반 UUID, 내용 SHA-256으로 식별·중복 제거한다. 짧거나 너무 긴 본문은 자동으로 잘라 사실관계를 손상시키지 않고 검토 대상으로 제외한다.
3. 반입 시 LLM은 BCP-47 원문 언어 판별과 감성·짧은 주장 라벨만 생성한다. 전체 번역은 생성하지 않는다. 불확실한 감성은 unknown으로 처리한다. 화면의 언어 목록은 자주 쓰는 필터이며, 그 외 언어 원문도 `모든 언어`에서 검색할 수 있다.
4. 원문 제목+본문을 1,800자, 200자 겹침 단위로 임베딩하고 평균 벡터로 문서 단위 색인한다. Qdrant에 1,536차원 벡터와 언어·출처·시각 필터를 저장한다. 원문은 D1에 보관한다.
5. 검색 시 다국어 질의 임베딩과 D1 원문 키워드 후보를 RRF로 결합한다. 선택적 LLM 재순위화가 상위 후보의 주제 적합도를 판단한다.
6. AI 번역 버튼을 누르면 현재 표시된 다른 언어의 결과만 목표 UI 언어로 번역한다. 원문 해시가 바뀌면 기존 캐시는 사용하지 않는다.
7. 선택 비교는 원문을 LLM에 직접 전달해 현재 UI 언어로 분석한다. 인용은 번역하지 않고 원문과 정확히 일치하는 문자열만 허용한다.
8. 보고서는 검색된 실제 ID와 원문 발췌로 구성하고 원문 링크를 제공한다.

현재 키워드 검색은 SQL LIKE 후보 검색이다. BM25나 언어별 형태소 분석기를 구현했다고 주장하지 않는다. 데이터와 동시 요청이 증가하면 실제 지연시간과 스캔량을 측정해 FTS5 trigram 또는 별도 검색엔진으로 전환한다. 전환 기준은 고정 문서 수가 아니라 p95 지연시간·DB 읽기량·검색 품질이다. 현재 보고서의 통계는 상위 최대 30건에 대한 통계이며 전체 검색 모집단 통계가 아니다.

## 데이터 확대 원칙

고정된 언어별 문서 수는 출시 조건으로 사용하지 않는다. 먼저 승인된 출처에서 실제 원문을 소량 반입하고, 검색 실패 사례가 확인되는 언어·주제·지역을 우선 보강한다. 원문 한 건을 번역해 여러 건으로 중복 집계하지 않으며 합성 예시도 실제 수집량에 포함하지 않는다.

운영 대시보드는 전체 문서 수 외에 출처 집중도, 최근성, 언어·지역·주제 분포, 중복률, 원문 링크 유효율을 함께 본다. 한 출처 비중이 지나치게 높거나 특정 기간에 몰리면 수량이 많아도 출시 근거로 사용하지 않는다. 각 출처의 이용 조건, 보존/삭제 방식, 재배포 가능 범위를 검토한 뒤 활성화하며 인증·유료벽·봇 차단을 우회하는 커넥터는 포함하지 않는다.

Agent Reach는 자체 상용 수집 API가 아니라 로컬 Agent가 플랫폼별 CLI·브라우저 세션을 선택하도록 돕는 capability layer이다. Cloudflare 런타임과 직접 연동하지 않으며, 필요하면 배포를 분리한 관리자 탐색 worker에서만 실험한다. 세부 판단은 `docs/AGENT_REACH_REVIEW.md`에 기록했다.

## 검색 품질 평가

언어별 최소 200개 사람이 판정한 질의를 준비한다. 동일 사건·스레드가 개발과 평가 양쪽에 들어가지 않도록 시간/주제로 분리한다. 종목 별칭(삼성전자/005930/Samsung Electronics), 동음이의어(Apple/사과), 반어·혼합 언어·부정문·스팸 질의를 포함한다.

- Recall@10, nDCG@10, MRR@10: `pipeline/evaluate.py`.
- 비교 실험: 키워드 단독 → 벡터 단독 → RRF → 재순위화.
- 추가 수동 평가: 요청 시 번역의 충실도, 번역 캐시 무효화, 근거 인용 정확성, 감성 macro-F1, 군집 적합성, 유해 발언 오탐·미탐.
- 제안 출시 기준: Recall@10 ≥ 0.85, nDCG@10 ≥ 0.80, 인용 정확성 ≥ 0.98. 이 값은 목표이지 측정 결과가 아니다.
- 언어별 최저 점수를 확인한다. 평균 점수만으로 약한 언어를 숨기지 않는다.

## 토론과 Barrier

ChatGPT 로그인으로 작성자를 식별한다. D1에 토론방·메시지·보고서를 저장하고 4초 폴링으로 다른 사용자의 발언을 받는다. 토론방은 로그인한 누구나 참여할 수 있으며 생성자가 자기 보고서를 공개하기로 선택할 때 개설된다. 방 개설 화면에 보고서 공유를 고지한다.

서버가 입력 길이, 로그인, 계정 정지, 시간당 요청량을 확인한다. OpenAI moderation 및 추가 문맥 기반 정책 검사를 모두 통과한 뒤 메시지를 저장한다. 검사 실패/키 미연결은 fail-closed다. 위협/혐오 위협 감지 시 24시간 정지하고 관리자가 해제할 수 있다. 일반 차단은 발언을 저장하지 않는다. 감사 로그에는 원문 대신 조치 이유를 보관한다.

시민적 반대 의견, 윤리적 논쟁, 유해행위에 대한 학술적 설명은 허용하는 정책이다. ‘비도덕적’이라는 추상적인 판단만으로 사람을 영구 추방하지 않는다. AI도 같은 검사를 거친다. 절대적인 유해발언 차단이나 완벽한 다국어 오탐 방지는 보장하지 않는다. 전용 신고/이의 신청 양식과 상시 검토 인력은 출시 전 추가 운영 사항이다.

AI 분석가와 반론 검토자는 같은 LLM의 서로 다른 역할 프롬프트이며 독립된 사실 검증자 2명은 아니다. 사람과 명확히 구분해 표시한다. 최근 40개 메시지를 바탕으로 발언하고, 최종 보고서는 전체 메시지를 40개씩 검토하여 원문과 정확히 일치하는 대표 발언을 발췌하고 전체 기록을 첨부한다. 한 방은 최대 500개 발언으로 제한한다.

## 음성 기능의 범위

사용자가 브라우저 마이크 권한을 허용하면 SpeechRecognition으로 음성을 텍스트 초안으로 만든다. 사용자가 검토 후 전송하면 서버 Barrier가 검사한다. 승인된 마지막 발언을 SpeechSynthesis로 읽을 수 있다. 원본 오디오는 앱이 저장하지 않으며 브라우저 제공자의 음성 인식 서버를 사용할 수 있다.

이 버전은 음성 입력을 이용한 턴 방식 토론이다. 동시 음성 스트리밍 회의, WebRTC SFU, 통역 오디오 채널, 끼어들기 지원은 구현하지 않았다. 실시간 오디오에는 오디오 전달 전에 검사를 적용하기 어려우므로 별도 지연·차단 설계가 필요하다.

## 보고서

1–5개의 페이지 객체를 생성해 화면에 표시하고 A4 인쇄/PDF 저장을 제공한다. 텍스트 길이를 제한해 한 페이지 안에 배치한다. 브라우저의 글꼴·인쇄 설정에 따라 물리 페이지 수는 달라질 수 있다. PDF 렌더러 서버나 DOCX 내보내기는 포함하지 않는다. 전체 원문 링크는 보고서 화면 하단에 있으며 인쇄에서는 본문 인용 ID가 유지된다.

## 운영 한계 및 남은 검증

실제 LLM/Qdrant 키 없이 유료 호출을 실행하지 않았다. 다국어 실제 corpus를 수집·학습했다고 주장하지 않는다. 외부 API 라이브 통합·음성 브라우저 호환성·동시 사용자 부하·모더레이션 품질·PDF 실제 페이지 QA는 미완료다. UI 빌드 통과는 서비스 품질 인증이 아니다.
