# VMAX 관리자 사용설명서

문서 버전: 0.1 · 배포 후보 MVP

## 1. 무엇이 준비됐는가

다국어 검색 UI, 검색 서버, 수집 데이터 반입 API, Qdrant 의미 검색, 요청 시 LLM 번역과 번역 캐시, 의견 비교, 1–5페이지 보고서, 로그인 기반 공유 토론방, 서버 전송 전 검사, AI 참여자 2명, 음성 입력/읽기, 최종 토론 요약이 코드에 포함되어 있다.

현재 실제 수집 corpus는 0건이며 UI에는 합성 예시 6건을 명시적으로 표시한다. 출처별 실제 데이터 확보와 언어·주제별 검색 정확도 평가를 완료한 서비스가 아니다. API 키를 설정하기 전 AI 번역·비교·토론 전송은 의도적으로 차단된다.

## 2. 서버 설정

다음 값은 배포 서비스의 **서버 환경변수/Secret**에 입력한다. GitHub의 코드, 브라우저의 localStorage, NEXT_PUBLIC_ 환경변수, 채팅 메시지에 API 키를 넣지 않는다. 사용자가 키를 직접 입력하는 방식이며 키가 들어갈 자리는 `.env.example`에 있다.

| 이름 | 용도 | 비밀 값 여부 |
|---|---|---|
| OPENAI_API_KEY | 재순위화, AI 토론, moderation, 질의 임베딩 | Secret |
| LLM_MODEL | 기본 `gpt-4.1-mini`; 계정에서 지원되는 모델로 변경 가능 | 아니오 |
| EMBEDDING_MODEL | 기본 `text-embedding-3-small`; 색인과 검색을 동일 모델로 유지 | 아니오 |
| QDRANT_URL | HTTPS Qdrant 서버 주소 | 아니오 |
| QDRANT_API_KEY | Qdrant 접근 키 | Secret |
| QDRANT_COLLECTION | 기본 `polylogue` | 아니오 |
| INGEST_TOKEN | 관리자 반입 전용의 충분히 긴 무작위 토큰 | Secret |
| ADMIN_EMAILS | 관리자 ChatGPT 로그인 이메일, 쉼표로 구분 | 개인정보 |

ChatGPT 구독만으로 이 앱의 API 호출 권한을 얻는 것은 아니다. 실제 API 계정·한도·결제 상태를 확인한다. 가격은 모델·사용량에 따라 달라지므로 고정 비용을 약속하지 않는다. 원문을 AI 제공자에게 전송하는 처리는 각 출처의 이용 가능 범위와 개인정보 정책에 맞게 결정한다.

환경변수 변경 후 재배포해야 새 설정이 적용된다. API와 DB 연결 상태는 공개 화면에서 제거했다. 상세 발급·비용 안내는 OWNER_REPORT.md를 참고한다. 본인 이메일을 ADMIN_EMAILS에 넣고 재로그인하면 관리자 요청 권한을 사용할 수 있다. 공개 운영 패널은 제거했다.

## 3. GitHub에 올리기

1. 소스 ZIP을 내려받아 압축 해제한다.
2. 새 private 저장소 `polylogue`를 만든다.
3. README, app, components, lib, db, drizzle, scripts, build, pipeline, docs, tests, public, 설정 파일과 lockfile을 올린다.
4. `.env`, `.dev.vars`, node_modules, dist, data, .git, .sites-runtime는 업로드하지 않는다. ZIP은 이 항목을 제외하도록 생성된다.
5. `.github/workflows/check.yml`이 타입 검사, Python 테스트, 빌드를 실행한다.

`.openai/hosting.json`의 project_id는 이번 Site의 정체성이다. 원래 Site를 관리할 때 보존한다. 독립적인 새 Site로 복제할 때는 새 등록 절차로 발급받은 ID를 사용한다. 임의 ID를 만들어 넣지 않는다.

현재 GitHub 저장소에 직접 push하지 않았으며 사용자 다운로드 업로드가 기본 전달 경로다. GitHub Pages는 서버 API·DB가 필요한 이 앱의 배포 대상이 아니다.

## 4. 로컬 개발과 빌드

Node 22.13 이상, package.json에 지정된 pnpm, Python 3.11 이상이 필요하다. 저장소 루트에서 실행한다.

```bash
corepack enable
pnpm install --frozen-lockfile
pnpm exec tsc --noEmit
python -m unittest discover -s tests
pnpm build
pnpm dev
```

로컬 키는 `.env.example`을 `.dev.vars`로 복사해서 입력한다. 프로젝트를 다른 컴퓨터로 옮기면 `.sites-runtime`를 복사하지 않는다. 현재 Site는 Cloudflare Workers 기반 Vinext와 Sites의 인증·D1 배포 연결을 사용한다. 임의 Vercel 배포로 동일하게 동작하지 않는다.

## 5. 언어별 데이터 확보

### 입력 형식

JSONL 한 줄에 한 원문이다. `publishedAt`은 시간대가 포함된 실제 게시 시각이어야 한다.

```json
{"title":"원문 제목","body":"최소 40자 이상의 실제 원문 본문...","source":"허가된 출처명","url":"https://example.com/posts/123","publishedAt":"2026-09-15T01:00:00Z"}
```

예시 도메인은 데이터가 아니다. 실제 허가된 원문으로 대체한다. JSONL 데이터를 코드 저장소에 넣지 않는다.

### HN 공식 수집기

```bash
python pipeline/collect_hn.py --limit 200 --output data/hn.jsonl
```

공식 API에서 story/comment 본문만 수집하며 링크 대상 기사는 수집하지 않는다. `data/hn.cursor`로 중단 후 재개한다. 한 번의 실행 건수는 --limit로 제한한다. HN만으로 한국어·프랑스어 quota를 채울 수 없다. 다른 출처는 공식 API/계약된 데이터 제공처를 통해 같은 JSONL 스키마로 반입한다.

### 검증과 색인

먼저 네트워크/AI 비용 없이 입력 구조를 검증한다.

```bash
python pipeline/index_corpus.py data/hn.jsonl --dry-run --max-documents 200
```

환경변수에 OPENAI_API_KEY, QDRANT_URL, QDRANT_API_KEY, SITE_URL(배포 주소), INGEST_TOKEN을 설정한 다음 실행한다.

```bash
python pipeline/index_corpus.py data/hn.jsonl --max-documents 100
```

- 먼저 100건으로 번역·언어·감성 오류를 검토한다.
- 최대 1회 100건이 기본값이며 늘리면 API 비용이 늘어난다.
- `data/index.sqlite`에 성공 기록과 AI 전처리 결과를 저장하여 재개한다. 이 파일도 백업한다.
- 기존 같은 URL의 내용 변경은 원문을 갱신한다. 내용이 같은 중복은 제외한다.
- 수동 검수된 language, sentiment, stance가 이미 있는 입력은 --reviewed로 반입할 수 있다. 전체 번역 필드는 필요하지 않으며 임베딩 API는 여전히 호출된다.
- 문서 수를 언어별 고정 quota로 관리하지 않는다. 출처·지역·주제·기간 분포와 실제 검색 실패 사례를 보고 필요한 원문을 우선 보강한다. 번역 복제본과 합성 예시는 corpus 수에 포함하지 않는다.
- 사용자가 AI 번역을 누르면 현재 표시된 결과만 UI 언어로 번역한다. 번역은 원문 해시와 목표 언어 기준으로 D1에 캐시되며 원문이 변경되면 다시 생성한다.
- Qdrant vector dimension은 1536이며 변경 시 새 collection을 구축하고 서버와 수집기의 모델 설정을 함께 변경한다.

현재 수집기에 Reddit/Naver/디시인사이드/Weibo 등의 자동 수집 구현은 없다. ‘모든 유명 커뮤니티’에 접근 가능한 공통 API는 이 프로젝트에 제공되지 않는다. 출처별 접근권한과 연결 구현은 별도 확장 작업이다.

## 6. 사용자 기능 운영

탐색 → 실제 수집 데이터 → 검색어/언어/기간/출처 → 검색. 키가 없으면 키워드 검색만 동작한다. 의미 검색은 로그인과 AI/Qdrant 연결이 필요하다. 실패 시 경고와 키워드 결과를 보여준다.

게시글 2개 이상 체크 → 의견 비교 → 선택 의견 비교. 감성(긍정/부정)과 주장(왜 그렇게 생각하는지)을 분리해서 검토한다. 보고서는 선택 의견 또는 현재 표시 결과를 대상으로 만든다.

보고서 만들기 → 1–5페이지 선택 → 생성 → 인쇄/PDF 저장. A4, 100% 배율, 머리글·바닥글 해제 권장. 본문은 원문 직접 발췌이며 번역·감성 라벨에는 오류가 있을 수 있다.

보고서 목록 → 공개 토론 개설. 이 동작은 보고서 내용을 로그인한 참여자에게 공유한다. 다른 참여자가 없어도 AI 2명 참여 버튼으로 분석가와 반론 검토자의 발언을 생성한다.

마이크 버튼 → 브라우저 권한 허용 → 음성 입력 → 초안 확인 → 전송. 원본 음성을 다른 사람에게 실시간 송출하는 회의 기능은 아니다. 마지막 발언 듣기로 텍스트를 읽을 수 있다. 브라우저 미지원이면 텍스트 입력을 사용한다.

방 개설자만 종료/요약 버튼을 사용할 수 있다. 모든 메시지를 구간별로 검토해 원문 일치 발언을 발췌하고 전체 기록을 개인 보고서에 첨부한다. 요약 중에는 신규 발언을 잠그고 전체 기록을 읽는다. 런타임이 강제 종료되어 closed=2에 멈추면 DB에서 이전 상태로 복원 후 다시 요약한다.

## 7. 안전·장애 대응

| 증상 | 확인/조치 |
|---|---|
| 로그인 필요 | 상단 로그인 버튼, ChatGPT 계정 확인 |
| AI 키 필요 / 503 | 서버 OPENAI_API_KEY 설정 후 재배포 |
| 제공자 응답 실패 / 502 | API 한도, 결제, LLM_MODEL 접근권한 확인 |
| 의미 검색 실패 | Qdrant HTTPS 주소/키/collection, 1536차원, metadata index 확인 |
| 429 | 사용자별 시간당 한도, AI 비용 대시보드 확인 |
| 결과 없음 | 실제 데이터 유무, 기간, 언어, 출처 필터 확인 |
| 발언 차단 | 사용자가 인신공격 등을 수정; 오탐이면 관리자 검토 |
| 계정 정지 | 관리자 전용 요청으로 이유 검토 후 해제 가능 |
| DB 장애 | 입력을 보존하고 재시도; 운영 콘솔에서 DB와 migration 확인 |
| 수집기 중단 | 동일 state/cursor를 유지하고 재실행 |

기본 한도: 발언 60회/시간, 보고서 10회/시간, 비교 15회/시간, AI 토론/요약 12회/시간, 의미 검색 60회/시간, 재순위화 30회/시간. 운영 규모에 맞게 lib/server.ts 및 route 호출값을 조정한다. 가입자 전체 비용 한도/봇 방어는 제공자 예산 제한과 추가 gateway 제한을 적용해야 한다.

유해 발언 검사는 키가 없거나 실패하면 메시지를 통과시키지 않는다. AI 답변도 검사한다. 이 보호는 완벽하지 않다. 운영자는 오탐과 미탐을 언어별로 검토해야 한다.

## 8. 삭제·보존·백업

D1과 Qdrant는 분리된 저장소다. 게시글 삭제는 `/api/admin`의 deletePost로 D1 노출을 즉시 막은 후 Qdrant의 같은 ID 벡터를 삭제한다. 이미 생성된 보고서는 원문 스냅샷을 포함하므로 해당 payload와 파생 토론도 별도로 찾아 삭제/비식별화해야 한다. 자동 전파 삭제 작업은 아직 없다.

일일 DB 백업, Qdrant snapshot, 데이터 제공처의 삭제 요청 처리, 감사 로그 보존 기한, 운영자 연락처/이의 접수 경로는 출시 전에 지정한다. limits 테이블은 시간당 버킷이므로 정기적으로 오래된 행을 정리한다. 자동 백업과 스케줄러는 이번 코드에 설정하지 않았다.

## 9. 배포와 출시 점검

Sites 배포는 프로젝트 소스와 D1 migration을 함께 저장한 버전을 배포한다. 인터넷 공개는 접근 설정을 public으로 선택한다. 읽기는 공개되더라도 토론·보고서 생성에는 로그인이 필요하다. 별도의 외부 서버에 배포하려면 인증 프록시와 DB 바인딩을 다시 구현해야 한다. 외부 서버에서 사용자 제공 `oai-authenticated-*` 헤더를 그대로 신뢰하면 안 된다.

승인된 실데이터 확보, 주요 언어·주제별 검색 평가, 요청 시 번역 검수, 원문 이용 승인, 실제 API 키 통합, 두 사용자 동시 토론, 음성 인식, 보고서 출력, 삭제 전파/보존 정책, 비용/요청 제한 검증이 끝나기 전에는 완성된 상용 서비스로 홍보하지 않는다.

## 10. 작업 재개

`docs/STATUS.md`에 구현·검증·미완료 항목이 기록되어 있다. 원문 수집과 색인은 checkpoint로 재개할 수 있다. 대화 토큰/사용량 한도 초기화를 자동 감지해서 ChatGPT가 스스로 다음 작업을 시작하는 기능은 제공되지 않는다. 작업이 끊기면 코드와 STATUS.md를 첨부하거나 같은 대화에서 ‘이어서 진행해줘’라고 요청한다. 무인 운영은 별도의 사용자 소유 scheduler/worker와 예산 제한을 구성해야 한다.
